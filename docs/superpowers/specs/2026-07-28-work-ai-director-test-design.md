# 工作 APP AI 导演测试设计

## 目标

在工作 APP 的“工作设置”中增加“测试 AI 导演”按钮。测试必须覆盖办公室实际依赖的主 API 请求能力，而不只检查模型列表接口。成功和失败都向用户显示清晰结果。

## 范围

- 测试当前选中的主 API。
- 使用与办公室 AI 导演相同的 `/chat/completions` 地址、鉴权方式、模型和超时规则。
- 使用最小办公室场景请求，并校验响应是否为可用的办公室场景计划。
- 不修改全局 API 设置页面的现有“获取模型”和“测试连接”行为。
- 不测试副 API，也不改变现有副 API 回退顺序。

## 交互设计

“工作设置”在 A/B 自主行为模式选项下方增加一个独立测试区：

- 默认按钮文案：“测试 AI 导演”。
- 请求期间按钮禁用，文案：“测试中…”。
- 成功后显示成功提示：“AI 导演连接成功，可以使用。”
- 失败后显示错误提示，并保留可理解的具体原因。
- 连续点击只保留最近一次测试结果，避免旧请求覆盖新结果。

测试按钮不自动切换 A/B 模式，不修改当前办公室计划，也不触发人物移动。

## 数据流

1. 工作设置触发测试回调。
2. 从 `ccat-ai-api-configs` 读取当前 API 配置。
3. 校验主 API 是否包含 API Key、Base URL 和模型标识。
4. 调用与 AI 导演相同的请求函数，发送一个最小、确定性的办公室场景请求。
5. 使用现有场景计划校验器验证响应。
6. 将结果转换为成功或具体失败提示并显示在工作设置中。

## 错误处理

失败提示至少区分：

- 主 API 未配置或模型为空。
- HTTP 401/403：凭证或权限错误。
- HTTP 404：接口地址或路径不兼容。
- HTTP 429：请求限流或额度不足。
- 请求超时或网络/CORS 失败。
- API 有响应，但返回内容不是有效的办公室场景 JSON。

自动 AI 调度失败时也保留实际错误原因，提示格式为“AI 导演暂不可用：具体原因。已使用本地调度”。不得再吞掉错误。

## 代码边界

- 在办公室 API 模块中提供可复用的主 API 测试函数和错误文案转换。
- `WorkSettings` 只负责按钮、加载状态和结果展示。
- `WorkAppScreen` 负责把测试能力传给设置页。
- `useOfficeSimulation` 继续负责自动调度，但显示规范化后的真实错误。

## 验收标准

- 完整有效的主 API 返回有效场景时，测试提示成功。
- Key、地址或模型缺失时，测试不发请求并显示对应错误。
- 401、404、429、超时、网络失败和无效 JSON 均显示可理解的具体失败原因。
- 测试不会切换 A/B 模式、改变计划或移动人物。
- 原有本地模式、AI 模式、项目管理和人物自主行为保持不变。
- 自动 AI 调度失败提示包含真实原因并继续安全回退本地调度。
- 单元测试、全量测试、生产构建和手机端工作 APP 浏览器验收通过后再部署。
