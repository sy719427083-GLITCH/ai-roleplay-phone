# Work APP 项目管理 UI 设计

## 目标

在 Work APP 中把“项目管理”占位页替换为适合手机浏览的纵向项目卡片列表。第一次进入时调用已配置的主 API 生成五个工作项目；本轮先制作使用固定示例数据的可视 UI 预览，确认视觉后再接真实 API 与持久化逻辑。

## 已确认方向

- 使用方案 A：五张纵向项目卡片，单列滚动。
- 延续 Work APP 现有的清新、克制、精致风格，沿用蓝、绿、紫、珊瑚色与系统字体。
- 不采用儿童化字体、橙色主视觉、厚重阴影或复杂卡片装饰。

## 页面结构

1. 顶部栏：左侧返回按钮，中间标题“项目管理”，右侧刷新按钮。
2. 状态摘要：显示“今日可接 5 个项目”；刷新锁定后改为“项目进行中 · 列表已锁定”。
3. 项目列表：固定展示五张纵向卡片。
4. 每张卡片包含：
   - 项目名称；
   - 难度标签；
   - 项目时间；
   - 项目金额；
   - 1–2 行项目内容；
   - 底部全宽“开始项目”按钮。

## 视觉规则

- 页面使用浅蓝白背景，卡片为清晰白色表面。
- 卡片圆角控制在 14–16px，使用轻边界或短阴影，不叠加厚重玻璃效果。
- 项目金额使用绿色强调；时间使用蓝色；难度使用带文字的彩色标签，不能只依赖颜色。
- 卡片间距 12px，页面左右留白 14–16px，所有按钮点击区域至少 44px。
- 内容超过两行时截断，避免单张卡片过高。

## 状态与交互

### 首次加载

- 第一次进入项目管理页时请求主 API。
- 请求期间显示五张骨架卡片，刷新按钮进入加载状态且不可重复点击。
- API 必须返回恰好五个项目；应用层校验并规范化名称、时间、金额、内容和难度。

### 刷新

- 未开始任何项目时，点击右上角刷新重新请求并整体替换五个项目。
- 刷新期间保留列表高度，用骨架或局部加载反馈，避免页面跳动。
- 任意项目开始后，整页刷新按钮禁用，不能替换当前五个项目。

### 开始项目

- 点击“开始项目”后，该卡片进入“进行中”状态。
- 按钮文字变为“项目进行中”，按钮禁用并显示清晰的状态差异。
- 其他项目保留在列表中，但不能再刷新整组项目。

### 错误与空状态

- 缺少主 API 配置时提示用户前往 API 设置，不显示伪造项目。
- 请求失败时显示内联错误状态和“重新获取项目”按钮，保留顶部导航。
- 返回数据不完整时按失败处理，不渲染残缺卡片。

## 数据边界

- UI 组件只消费规范化后的项目数组与加载、错误、锁定状态。
- API 请求、响应解析、缓存和项目开始状态由独立逻辑模块负责。
- 项目数据需要持久化，重新进入页面时不重复调用 API；只有用户主动刷新才重新生成。

## UI 预览范围

- 使用五条固定示例项目数据展示完整列表。
- 可预览正常列表、刷新加载、项目进行中和刷新禁用四种视觉状态。
- 本轮预览不调用真实 API、不写入正式项目状态，也不发布线上版本。

## 验证

- 在 375×812 与 390×844 两种手机尺寸检查顶部安全区、卡片滚动和按钮可见性。
- 验证刷新按钮和开始按钮点击区域至少 44px。
- 验证加载、禁用、错误状态都有文字提示，不只依赖颜色。
- 验证 `prefers-reduced-motion` 下不会出现必须依赖动画才能理解的状态。
