# 微聊会话页面丝滑过渡设计

## 背景

微聊会话列表与聊天页目前通过条件渲染直接切换。点击会话后聊天内容虽然已经能快速显示，但页面缺少视觉上的进入过程，因此用户会感到一次突兀的“瞬切”。返回列表时也存在相同问题。

## 目标

- 点击会话时呈现接近微信的页面推进感。
- 返回会话列表时完整反向播放退出动画。
- 动画不能延迟聊天内容加载，也不能降低滚动和点击响应。
- 保持现有会话、消息、API 对话和历史分段加载逻辑不变。
- 兼容系统“减少动态效果”设置。

## 动效设计

采用双层页面推进：

- 进入聊天页时，聊天层从视口右侧滑入到原位。
- 下方会话列表同步向左轻移，并略微压暗，形成自然的前后层级。
- 聊天层左侧添加柔和阴影，强调页面覆盖关系。
- 返回时反向播放：聊天层向右滑出，会话列表复位并恢复亮度。
- 动画时长约 280ms，使用前快后柔的缓动曲线 `cubic-bezier(0.32, 0.72, 0, 1)`。
- 不加入头像放大、标题飞入或明显缩放，避免视觉负担。

## 交互状态

页面过渡划分为四个状态：

1. `list`：仅显示会话列表。
2. `entering`：聊天页已经挂载，执行进入动画。
3. `chat`：聊天页稳定显示并正常交互。
4. `leaving`：保留当前聊天页，先执行退出动画，结束后再清除当前会话。

进入动画期间锁定重复的会话点击；返回动画期间锁定重复返回操作，避免快速连点导致闪屏或状态错乱。动画结束由事件驱动，同时保留短暂超时兜底，防止浏览器未触发结束事件时卡在过渡状态。

## 实现边界

- 将会话列表与聊天页放进同一个页面舞台，在过渡期间允许两层同时存在。
- 使用 `transform`、`opacity` 和阴影完成动画，避免触发布局重排。
- 点击会话后立即设置当前会话并挂载聊天内容，动画仅负责视觉呈现。
- 返回时先进入退出状态，动画完成后再沿用现有关闭会话逻辑。
- 不改变消息存储结构，不新增第三方动画依赖。

## 无障碍与异常处理

- 当 `prefers-reduced-motion: reduce` 生效时，将位移和压暗效果取消，并把过渡缩短为接近即时切换。
- 动画样式失效或结束事件缺失时，兜底计时器确保页面仍能完成进入或返回。
- 浏览器后台切换、快速返回及组件卸载时清理计时器，避免卸载后更新状态。

## 验证标准

- 点击任一会话，聊天页从右侧平滑进入，列表同步轻微向左退。
- 点击返回，聊天页向右退出，列表同步复位，不发生瞬切。
- 快速连续点击会话或返回不会叠加动画、闪屏或进入错误会话。
- 首屏仍只渲染最近 120 条消息，现有消息功能与滚动定位不回退。
- 动画主要运行在合成层，手机浏览器交互保持流畅。
- 减少动态效果模式下可以近乎即时完成切换。
- 聚焦测试、完整测试及生产构建通过。
