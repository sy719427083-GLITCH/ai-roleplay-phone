# Work APP 茶水间 / 员工餐厅场景设计

## 目标

在现有 Work APP 办公室右侧增加一个小型场景入口，进入新的“茶水间 / 员工餐厅”合并场景。新场景延续当前办公室的白色未来建筑风格，使用独立底图与可点击透明设施 PNG；“我 APP”人物可通过真实寻路走到各设施旁，并在到达后显示简短行为提示。

## 已确认范围

- 茶水间和员工餐厅合并为一个场景，不增加场景选择页。
- 使用分区式布局：设备集中在上方和两侧，无椅餐桌位于中下部，中央保留连续通道。
- 餐桌不配置椅子。
- 办公室原茶水吧台替换为可点击的“智能打印资料区”。
- 新场景内设施点击后，人物自动走到设施旁并显示约 2 秒提示。
- 延续现有控制规则：只有已安排到办公室的“我 APP”人物可移动。
- 不新增业务功能、奖励、数值或新的持久化数据。

## 场景与导航

### 办公室入口

- 办公室屏幕右侧中部显示一个悬浮小箭头。
- 箭头使用至少 44 × 44px 的触控区域，但视觉主体保持轻巧。
- 入口不得遮挡办公室家具、可点击物或底部导航。
- 点击后使用短促横向滑动过渡进入茶水间 / 员工餐厅。
- 新场景继续显示现有 Work APP 底部导航；项目管理、项目倒计时和员工管理入口保持原行为。

### 返回办公室

- 新场景左侧显示返回箭头，触控区域至少 44 × 44px。
- 点击后取消当前行走任务，以反向横向滑动过渡返回办公室。
- 返回办公室后，“我 APP”人物恢复到其已分配工位的默认位置。
- 场景往返不得更改员工安排、头像覆盖或项目状态。

## 视觉资产

### 底图

- 新底图使用与 `orbit-office-background.png` 一致的纵向构图和视觉语言。
- 风格要求：白色未来感建筑、圆角墙体、蓝天窗景、柔和自然光、淡蓝与浅紫点缀、干净明亮的地面。
- 底图只包含建筑空间和不可交互装饰，不把交互设施画死在底图中。
- 目标基准尺寸为 852 × 1846，允许生成后进行无损裁切或缩放以精确匹配。

### 独立可点击设施

以下设施分别使用透明 PNG，并在界面中以独立语义按钮叠加：

1. 饮品吧台
2. 咖啡机
3. 冰箱
4. 微波炉
5. 零食柜
6. 无椅员工餐桌
7. 办公室智能打印资料区

所有透明资产必须与底图共享透视、光向、材质和色彩。验收时检查透明边缘、悬空感、比例和落地位置。

## 分区式空间布局

- 上方左侧：饮品吧台。
- 上方右侧：咖啡机。
- 中上部左侧：冰箱。
- 中上部右侧：微波炉。
- 中下部：一张无椅员工餐桌。
- 下部右侧：零食柜。
- 左下部：人物入口及返回方向。
- 设施之间保留足够的可行走间距，中央形成连续主通道。

设施的视觉边界、碰撞边界和人物停靠点分开配置。碰撞边界以实际可见 PNG 占用范围为准，停靠点放在设施前方或侧前方的可行走地面上。

## 人物与交互

### 人物出现规则

- 若办公室中已安排“我 APP”人物，进入新场景后该人物从左下入口出现。
- 其他 Character APP 和 NPC 员工不进入新场景，也不可控制。
- 若没有“我 APP”人物，场景仍可浏览；点击设施时显示“请先在员工管理中安排‘我 APP’的角色”。

### 点击设施

点击设施后：

1. 根据人物当前位置、目标停靠点和设施碰撞区域生成路线。
2. 人物沿路线分段行走，不得穿过任何设施 PNG。
3. 行走时保持现有水平朝向和距离计时规则。
4. 到达后停止移动，并显示约 2 秒的行为提示。

行为提示如下：

| 设施 | 到达提示 |
| --- | --- |
| 饮品吧台 | 正在挑选饮品 |
| 咖啡机 | 正在制作咖啡 |
| 冰箱 | 正在查看冰箱 |
| 微波炉 | 正在加热餐食 |
| 零食柜 | 正在挑选零食 |
| 无椅员工餐桌 | 正在用餐 |
| 办公室智能打印资料区 | 正在处理文件 |

同一时间只执行一条路线。移动中再次点击设施不启动第二条路线；切换场景时立即取消计时器和未完成路线。

## 组件与模块边界

- `BreakroomScene`：只负责渲染新场景、设施按钮、人物和场景内提示。
- 茶水间设施配置：声明资产、语义标签、碰撞边界、停靠点和到达提示。
- 茶水间寻路模块：根据响应式场景尺寸生成避障路线，不依赖 React。
- `OfficeScene`：继续负责办公室渲染，并把茶水吧台替换为智能打印资料区。
- `WorkAppScreen`：持有 `office` / `breakroom` 当前视图，协调进入、返回、移动取消与人物起点。

模块之间使用明确的配置和回调传递数据，避免把新场景布局、寻路和提示逻辑继续堆入 `WorkAppScreen`。

## 状态与缓存

- 当前场景只保存在 React 内存状态中，Work APP 重新打开时仍从办公室开始。
- 不新增 localStorage 键。
- 现有 `ccatWorkCompanyV1`、`ccatWorkOfficeV1` 和 `ccatWorkProjectsV1` 结构保持兼容。
- “清除工作缓存”仍只清除上述三个键。
- 茶水间中的临时位置和行为提示不持久化。

## 错误与边界处理

- 没有“我 APP”人物：不移动，显示员工安排提示。
- 场景尺寸尚不可用：不移动，显示“茶水间路线暂时不可用”。
- 目标无有效路线：不穿越障碍，显示“这里暂时没有可通行的路线”。
- 设施图片加载失败：保留语义按钮和可点击区域，不阻塞返回办公室。
- 快速切换场景：取消旧计时器并忽略旧路线回调，防止人物状态跨场景串联。

## 测试与验收

### 自动化测试

- 办公室右侧入口和新场景返回入口存在，触控区域不小于 44 × 44px。
- 办公室不再声明茶水吧台，改为智能打印资料区。
- 新场景声明六个可点击设施，餐桌配置中不存在椅子。
- 所有设施具有独立资产、语义标签、停靠点和提示文案。
- 任意起点到任意设施的路线不穿过设施碰撞区域。
- 无路线、无人物和场景切换取消行为符合约定。
- 往返场景不修改员工安排、项目状态或缓存范围。

### 视觉与浏览器验收

- 在 390 × 844 视口验证两侧箭头、底部导航和设施互不遮挡。
- 新底图与现有办公室在透视、材质、光照和色彩上保持一致。
- 透明 PNG 无明显白边、色边、悬空、缩放模糊或落点偏差。
- 人物从左下入口出现，能绕开餐桌和两侧设备到达所有目标。
- 返回办公室后人物恢复工位，控制台无错误。

## 不在本次范围

- 多人物同时进入茶水间。
- NPC 自主用餐或随机移动。
- 咖啡、饮品、食物的制作 UI 或库存系统。
- 体力、心情、奖励或工作效率数值。
- 茶水间独立缓存、任务或项目逻辑。
