# 工作项目倒计时与报酬领取设计

## 目标

把工作 APP 的静态“工作倒计时”改成与已签署合同绑定的真实项目倒计时。项目到期后固定显示 `00:00:00`，用户必须主动点击“领取报酬”，对应金额才会以收入流水进入钱包 APP。领取成功后清空本批合同，下次进入项目管理时再通过真实 API 生成五份新合同。

## 已确认的产品规则

- 合同按现实时间计时，关闭工作 APP、刷新网页或关闭浏览器后仍继续。
- 超过 24 小时使用累计小时显示，例如三天从 `72:00:00` 开始。
- 到期后倒计时固定为 `00:00:00`，不得出现负数。
- 底部中央入口从“工作倒计时”改为“项目倒计时”。
- 项目到期后，入口主文案改为“工作结束”，小字显示“点击领取报酬”。
- 报酬不会自动入账；只有用户主动领取后才写入钱包。
- 每个项目报酬最多领取一次。
- 领取成功后清空已完成的合同批次；下次进入项目管理自动生成新的五份合同。
- 没有进行中项目时显示 `--:--:--` 和“项目倒计时”。

## 合同数据

### 新 API 返回结构

项目 API 改为要求每个项目返回以下规范字段：

```json
{
  "name": "项目名称",
  "durationHours": 72,
  "amountValue": 2100,
  "description": "项目内容",
  "difficulty": "中等"
}
```

- `durationHours` 必须是正整数，作为唯一计时依据。
- `amountValue` 必须是大于零的有限数字，最多保留两位小数，作为唯一入账依据。
- 界面中的“3 天”“¥2,100”由客户端根据规范数字生成，避免展示值与结算值不一致。
- API 仍必须一次返回正好五份合同；副 API 优先，失败后回退主 API 一次。
- 任一合同的数字字段无效时，整批响应失败并按既有回退规则处理，不使用示例合同兜底。

### 本地项目状态

`ccatWorkProjectsV1` 在现有字段上增加：

- `startedAt`：签署时的 ISO 时间；未签署时为 `null`。
- `endsAt`：`startedAt + durationHours`；未签署时为 `null`。

项目对象同时保存 `durationHours` 和 `amountValue`，并继续保存界面所需的 `duration` 与 `amount`。签署操作必须同时写入 `startedProjectId`、`startedAt` 和 `endsAt`。

旧缓存兼容规则：

- 尝试从旧字段中的“天/小时”和货币字符串转换规范数字。
- 旧的未签署合同转换成功后可继续使用。
- 旧的已签署合同转换成功但缺少时间戳时，以本次升级后首次恢复状态的时间作为真实开始时间。
- 无法可靠转换的缓存视为无效并清空；进入项目管理后重新调用 API 生成。

## 倒计时状态机

倒计时只依赖持久化的 `endsAt` 和当前 `Date.now()`，不通过递减内存数字累计时间，避免后台标签页节流造成误差。

状态如下：

1. `idle`：没有已签署项目，显示 `--:--:-- / 项目倒计时`。
2. `running`：当前时间早于 `endsAt`，每秒重算剩余秒数并显示累计小时格式。
3. `finished`：当前时间达到或超过 `endsAt`，固定显示 `00:00:00 / 工作结束 / 点击领取报酬`。
4. `claiming`：领取写入进行中，禁用重复操作。
5. 领取成功后回到 `idle`，同时清空合同批次。

剩余时间使用向上取整的总秒数：开始瞬间可准确显示 `72:00:00`，到期后钳制为零。组件挂载时立即计算一次，随后每秒更新，并在卸载时清理计时器。

## 界面与交互

### 办公室底部入口

- 无项目：大字 `--:--:--`，小字“项目倒计时”；点击进入项目倒计时页。
- 进行中：大字为实时累计小时倒计时，小字“项目倒计时”；点击进入详情页。
- 已结束：大字 `00:00:00`，状态文案“工作结束”，另提供可点击小字“点击领取报酬”。领取控件使用独立、可访问的按钮，不嵌套在另一个按钮中。

### 项目倒计时页

页面显示项目名称、合同报酬、约定工期、预计结束时间和大型实时倒计时。进行中显示“项目进行中”；到期后显示“工作结束”和明确的“点击领取报酬”按钮。没有已签署项目时显示“暂无进行中的项目”，并引导用户前往项目管理签署合同。

### 项目管理页

签署合同后立即开始真实倒计时。项目进行中和到期未领取期间，本批合同继续锁定，不能刷新或签署其他合同。领取成功清空本批合同后，下次进入项目管理按现有首次进入流程生成五份新合同。

## 钱包结算

把钱包本地存储的读取、写入和收入入账逻辑提取为共享模块，让工作 APP 与钱包 APP 使用同一套格式。项目报酬流水包含：

- 稳定且唯一的流水 ID：由项目 ID 与 `startedAt` 组合生成。
- 类型：`add`。
- 金额：合同的 `amountValue`。
- 描述：`项目报酬 · 项目名称`。
- 日期：沿用钱包当前日期格式。

领取流程先检查钱包中是否已有同一流水 ID：

1. 若不存在，写入收入并增加余额。
2. 若已存在，视为此前已成功入账，不再次增加余额。
3. 只有钱包写入成功或确认流水已经存在后，才清空项目状态。
4. 若读取或写入钱包失败，保持 `finished` 状态并展示错误，用户可重试。

这使连续点击、刷新恢复以及“钱包已写入但项目状态尚未清空时页面中断”等情况都不会重复发放报酬。

## 模块边界

- `workProjectApi`：验证 API 数字字段并生成统一项目对象。
- `workProjectState`：恢复、迁移、签署、结束判断和清空项目状态。
- 新的项目计时纯逻辑模块：格式化累计小时倒计时、派生 `idle/running/finished` 状态。
- 新的钱包存储模块：安全读取钱包、幂等添加项目收入。
- `ProjectManagementPreview`：签署时开始计时。
- `WorkAppScreen`：展示底部倒计时、倒计时详情页和领取操作。
- `OpenedApp` 钱包页面：改用共享钱包存储模块，保持现有钱包 UI 不变。

## 错误处理

- 无效或缺失的项目时长、金额不得进入可签署状态。
- 系统时间变化后始终以当前时间与 `endsAt` 的差值重算，不依赖上一次画面中的数字。
- 钱包写入失败时不得清空合同或标记已领取。
- 领取按钮在写入期间禁用，避免同一页面并发提交。
- API 密钥、完整接口错误和钱包原始数据不得显示在领取界面。

## 验证

### 纯逻辑测试

- 新 API 字段校验、展示文字派生及旧缓存迁移。
- 签署时正确记录开始和结束时间。
- `72:00:00`、最后一秒、到期归零及系统时间跨越。
- 项目未结束时禁止领取。
- 同一流水 ID 只能增加一次钱包余额。
- 钱包写入失败时项目保持可重试。
- 领取成功后项目批次为空，下一次进入触发现有 API 生成流程。

### 浏览器流程

- 签署合同后，办公室入口和详情页显示真实倒计时。
- 刷新页面后倒计时继续且没有重置。
- 将测试项目结束时间设为过去后显示 `00:00:00` 和“工作结束”。
- 点击“领取报酬”后钱包余额增加正确金额并出现项目收入流水。
- 重复点击或刷新恢复不会重复入账。
- 领取后进入项目管理会调用 API 生成新的五份合同。
- 在 375×812 和 390×844 两种视口完成布局与交互验证。

## 不在本次范围

- 暂停、加速或手动修改倒计时。
- 多个项目同时执行。
- 项目历史档案页。
- 自动领取报酬。
- 服务器端钱包或跨设备同步。
