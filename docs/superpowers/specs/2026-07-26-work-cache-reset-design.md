# Work APP 工作缓存清除设计

## 目标

在“工作设置”中增加“一键清除工作缓存”。清除成功后退出工作 APP；用户再次打开时，从工作 APP 启动动画、创建公司、进入公司动画重新开始。

## 清除范围

仅删除以下三个 Work 专用存储项：

- `ccatWorkCompanyV1`：公司名称与首次创建状态；
- `ccatWorkOfficeV1`：办公室员工安排、头像覆盖和人物位置；
- `ccatWorkProjectsV1`：项目列表、已开始项目和项目倒计时。

以下数据必须保留：

- 钱包余额、交易记录和已领取的项目报酬；
- 主 API 与副 API 设置；
- “我 APP”、角色和 NPC 资料；
- 其他 APP 的任何数据。

## 设置页

现有空白“工作设置”页改为正式设置页。页面保持当前 Work APP 的白蓝视觉，包含：

- 标题“工作设置”；
- 分组标题“存储与重置”；
- 说明“清除公司、办公室安排和项目进度，其他 APP 数据不会受到影响”；
- 红色描边按钮“清除工作缓存”。

按钮保持至少 44px 的触摸高度。

## 二次确认

点击“清除工作缓存”后，在 Work APP 内显示确认弹层，不调用浏览器原生 `confirm`。

弹层内容：

- 标题“清除工作缓存？”；
- 明确说明公司名称、员工安排、项目列表和倒计时会被删除；
- 明确说明钱包、API、角色资料不会被删除；
- 次按钮“取消”；
- 危险主按钮“确认清除”。

点击遮罩或“取消”关闭弹层，不修改任何数据。

## 清除行为

清除逻辑集中在独立纯函数中，依次删除三个明确的 Work 存储键，不遍历或模糊匹配 localStorage。

清除成功后：

1. 关闭确认弹层；
2. 调用 Work APP 的 `onClose`，返回手机主页；
3. 下次打开 Work APP 时重新初始化组件；
4. 因公司缓存不存在，进入启动动画和创建公司流程；
5. 新公司创建完成后，办公室为空，项目列表为空且没有倒计时。

选择退出后重新挂载，而不是只修改当前组件内的公司状态，可以避免内存中的旧办公室安排和项目状态在新公司创建后重新写回缓存。

## 失败处理

如果任意 `removeItem` 抛出异常：

- 不退出工作 APP；
- 保持设置页可操作；
- 关闭确认弹层；
- 显示“清除失败，请重试”；
- 不报告清除成功。

由于 localStorage 删除可能出现部分成功，用户再次点击确认时会安全地重复删除全部三个键。

## 验证标准

- 设置页能打开并显示清除入口。
- 第一次点击只打开确认弹层，不删除数据。
- 取消或点击遮罩不删除任何数据。
- 确认后只删除三个 Work 存储键，钱包、API、角色和其他 APP 数据保持不变。
- 清除成功后自动返回主页，再次打开 Work APP 播放启动动画并要求创建公司。
- 重新创建后办公室与项目状态为空。
- 删除失败时不退出并显示错误。
- 按钮触摸目标、键盘焦点和确认弹层语义可访问。
- 相关单元测试、全量测试、生产构建和 390 × 844 浏览器流程验证通过。
