# Work APP 项目合同真实 API 设计

## 目标与范围

项目合同页不再使用内置示例项目。首次进入且本地没有有效合同缓存时，通过用户现有 API 配置生成恰好五份合同；成功后缓存，主动“换一批”才重新生成。签署任意合同后持久化锁定状态。

## API 选择与回退

1. 优先选择有效副 API：副 API 开关已启用，且当前选中配置或副 API 草稿包含 `apiKey`、`baseUrl` 与 `model/customModel`。
2. 副 API 未配置时直接使用有效主 API。
3. 副 API 已配置但请求、HTTP、解析或校验失败时，自动使用主 API重试一次。
4. 主 API 缺失或主 API 重试仍失败时，显示错误状态，不回退到示例数据。
5. 页面显示最后成功来源“副 API 生成”或“主 API 生成”，不展示配置名称、Key 或地址。

## 请求协议

- 使用现有 OpenAI 兼容接口：`POST {baseUrl}/chat/completions`；若 `baseUrl` 末尾没有 `/v1`，先补 `/v1`。
- 请求头使用现有配置的 Bearer API Key 与 `Content-Type: application/json`。
- 模型使用配置中的 `model`，无值时使用 `customModel`；温度使用配置值，默认 `0.7`。
- 系统提示要求模型只输出 JSON，不使用 Markdown 代码围栏或解释文字。
- 用户提示要求生成适合创意工作室的五份不同合同，金额与工期合理，内容简洁。

## 响应 JSON 契约

根对象格式：

```json
{
  "projects": [
    {
      "name": "品牌活动海报",
      "duration": "5 天",
      "amount": "¥1,500",
      "description": "完成新品活动主视觉与海报排版。",
      "difficulty": "中等"
    }
  ]
}
```

校验规则：

- `projects` 必须是长度恰好为 5 的数组。
- 五个字段均为去除首尾空格后的非空字符串。
- `difficulty` 只接受“简单”“中等”“困难”，其他值判定整组失败。
- 名称最长 24 个中文字符等效长度，工期最长 12，金额最长 20，内容最长 100；超长内容安全截断。
- 每个项目在客户端生成稳定 ID，格式为 `api-{revision}-{index}`，API 不负责生成 ID。
- 支持从模型偶发返回的 Markdown JSON 代码围栏中提取 JSON，但不接受自然语言夹杂或缺字段对象。

## 状态与持久化

- 新存储键：`ccatWorkProjectsV1`。
- 缓存结构包含 `projects`、`startedProjectId`、`revision`、`source` 和 `generatedAt`，不包含 API 配置或密钥。
- 首次进入：无有效缓存时调用 API；有效缓存则直接恢复，不重复请求。
- 换一批：未签署时请求新合同；请求成功才原子替换旧列表并增加 `revision`，请求失败保留旧合同并显示错误。
- 签署：保存 `startedProjectId`，立即禁用换一批和全部签署按钮；重新进入仍保持锁定。
- 旧示例预览状态不迁移；无新缓存即视为首次进入。

## 页面状态

- 初始加载：显示五份合同骨架和“正在生成合同”。
- 有缓存：立即显示合同，不闪烁骨架。
- 刷新加载：保留当前合同在页面，顶部显示加载遮罩或状态；成功后整体替换，避免失败时列表消失。
- 无配置：显示“请先在 API 设置中配置主 API 或副 API”和“重新检查”按钮。
- 双 API 失败：显示最后一个可读错误和“重新获取合同”按钮。
- 签署后：继续显示红色“已签署”印章，来源标签保留，刷新锁定。

## 模块边界

- `workProjectApi.js`：选择端点、构造请求、解析与校验 API 响应、执行副 API 到主 API 的回退。
- `workProjectState.js`：创建、校验、序列化和恢复缓存状态；处理刷新成功与签署状态。
- `ProjectManagementPreview.jsx`：负责加载、错误、列表、签署和刷新 UI，不直接解析 API 配置或响应。
- `WorkAppScreen.jsx`：仅继续负责项目页导航，不持有合同业务状态。

## 安全与错误处理

- API Key 仅在请求头中使用，错误信息不得包含 Key、完整请求头或完整 API 响应。
- HTTP 错误只显示状态码；网络错误统一显示“网络请求失败”。
- 模型返回内容只作为文本解析，不使用 `eval` 或动态执行。
- 本地存储写入失败不得导致页面崩溃；合同仍保留在当前内存状态。
